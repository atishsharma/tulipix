Why there is a warning at all. A certificate is normally vouched for by an authority every device already knows, and none of them will vouch for a desktop on your own network — there is no name on the internet to check against. So the phone is asked to remember this one instead, the way it works when you connect to a machine over SSH. The connection is encrypted either way; the warning is about who is on the other end, and the fingerprint above is how you answer that. The PIN and the paired-device list are still what decide who can see your files.

Optional

Make the warning go away for good

Installing this desktop's certificate authority removes the warning entirely. It is worth it on a laptop you use constantly. It is not worth it on an Android phone: Android treats any hand-installed authority as a reason to fail its integrity check, and banking, payment and some work apps refuse to run on a phone carrying one. If you installed it before and your banking app stopped working, that is why — remove it under Settings → Security → Encryption & credentials → User credentials, and use the Continue button above instead.

tulipix-ca.crt · tulipix-ca.pem

Linux desktop

Browsers on Linux ignore the system certificate store and keep their own, which is why copying the file into /usr/local/share/ca-certificates changes nothing in Chrome or Firefox. This script writes to the right ones, and needs no root: 

curl -fsSL http://HOST/tulipix-ca-install.sh | sh

Or download it, read it, and run it. Restart the browser afterwards. Needs certutil — libnss3-tools on Debian and Ubuntu, nss-tools on Fedora, nss on Arch.

Windows and macOS

Windows: open tulipix-ca.crt → Install Certificate → Current User → Trusted Root Certification Authorities.

macOS: open tulipix-ca.pem in Keychain Access under login, find Tulipix Local CA, expand Trust and set Always Trust.

Leave this page open — it goes through on its own once this device trusts the certificate.
